```

```

## カード1：mrecレシート処理_撮影

- 説明カード表示：「写真を撮る / 画像から文字を読み取る / ChatGPTで分析する / メモを保存する」
- 画像：`images/01_satsuei_overview.png` 〜 `04_satsuei_save.png`

**アクション構成**

1. **テキスト**：`mrec_` + `現在の日付` + `時間`
2. **変数に追加**：テキスト → 変数 `name`
3. **写真を撮る**：1枚の写真を「背面」カメラで撮る
4. **テキストを抽出**：写真からテキストを抽出（iOS標準のOCR）
5. **テキスト**：`抽出されたテキスト`
6. **テキスト**（プロンプト本文）→ カード5参照。`text:` の下に `抽出されたテキスト` を差し込み
7. **ChatGPTを使用**：入力＝直前のテキスト（プロンプト）
8. **ファイルに追加**：`応答` を `01_mrec` へ追加
   - ファイルパス：`name` + `.md`
   - 新しい行を作成：オン

メモ：手順5の「テキスト」アクションは中身が `抽出されたテキスト` だけ。プロンプト側は抽出テキストを直接参照しているので、なくても動く可能性あり（記事で触れるか検討）。

## カード3：mrecレシート処理_テキスト

- 説明カード表示：「ChatGPTでレシートを分析し、メモボックスに記録する」
- 画像：`images/05_text_overview.png` 〜 `08_text_save.png`

**アクション構成**

1. **テキスト**：`mrec_` + `現在の日付` + `時間`
2. **変数に追加**：テキスト → `name`
3. **テキスト**：`毎回尋ねる`（実行時に入力ダイアログ）
4. **テキスト**（プロンプト本文）：`text:` の下に手順3の `テキスト` を差し込み
5. **ChatGPTを使用** → 6. **応答を `01_mrec` へ追加**（`name.md`、新しい行を作成オン）

- 用途の候補 ❓要確認：
  - ネット通販の購入明細メールを貼り付ける
  - 写真アプリの「テキスト認識表示」でコピーした文字を貼る
  - 口頭メモ／音声入力でざっくり入力

## カード4：mrec今日の出費

- 説明カード表示：「入力内容をメモとして保存する」
- 画像：`images/09_shuppi_overview.png`, `10_shuppi_actions1.png`
- **ChatGPTを使わない**手入力用。レシートがない支出（現金・自販機・割り勘など）向けと思われる ❓要確認
- 最後の `[spend::...]` 行をChatGPT版と同じ形にそろえている → どちらで登録しても同じ集計に入る

**アクション構成（見えている範囲）**

1. **テキスト**：`毎回尋ねる`
2. **変数に追加**：テキスト → `本文`
3. **テキスト**：`mrec_` + `現在の日付` + `時間`
4. **変数に追加**：テキスト → `タイトル`
5. **テキスト**：フロントマター付きの本文を組み立てる。最後の行は
   ```
   ---
   title: <タイトル>
   ...（途中はスクショ外 ❓）
   ---
   <本文>

   [spend::2026-mm,食費,xxx]
   ```
   - `[spend::...]` は**実行のたびに中身を書き換えて使う**（月・費目・金額）
   - ChatGPT版と同じ形式の1行を自分で書くので、手入力の支出も同じ集計にまとめて入る
6. 保存アクション（`01_mrec` へ追加と思われる ❓）

## カード5：ChatGPTに渡すプロンプト（#1〜#3共通・全文）

```markdown
# レシートテキスト
text: 
{抽出されたテキスト ※テキスト版は入力テキスト}

# 目的
・画像のテキストからmdファイルを作成する
・次の指示1〜3を順番に実行して下さい

# 指示1【必要情報を抽出】
［text］の中から合計金額と店舗名、購入日、各商品とその商品の値段を抽出して下さい
sum: 合計金額（桁区切りなし）
store: 店舗名
date: 購入日（YYYY/MM/DD）
month: 購入月（YYYY-MM）
dt: 購入日(YYYY-MM-DD HH:mm）
detale: 各商品とその商品の値段

# 指示2
費目の分析
[detale]からレシートの費目を分析して次の選択肢から1つ選んで下さい
選択肢: 
{食費,医療費,教育費,日用品費,税社保料, 保育費,ガソリン代,外食費}
食費は主に食料品を指します
医療費は病院の治療費と薬局の薬代を指します。

category:分析結果

# 指示3【ファイルタイトルの作成】
mdファイルの名前を[title]にして下さい
title: mrec_[dt]
# 次のフォーマットでMarkdown記法を適用せず、生のテキストとして出力してください


---
title: [title]
tags: mrec[date]
dt: [dt]
---
[info]

[spend::[month],[category],[sum]]
```

### 想定される出力（プロンプトから組み立てた例・数値は架空）

```markdown
---
title: mrec_2026-11-13 10:50
tags: mrec2026/11/13
dt: 2026-11-13 10:50
---
（商品と値段の一覧など）

[spend::2026-11,食費,1280]
```

❓実物は `01_mrec` フォルダの保存済みファイルで差し替える（下の「確認できなかったこと」参照）

### 記事で取り上げられるポイント

- **3段階の指示**：抽出 → 費目判定 → 出力整形、と順番に処理させている
- **費目を8つの選択肢から1つだけ選ばせる** → 表記がばらつかず集計しやすい。迷いやすい食費・医療費には定義を添えている
- **最後の1行 `[spend::月,費目,金額]`** がこの仕組みのキモ
  - Dataviewのインラインフィールド形式。全ファイル共通の1行なので、月別・費目別に集計できる
  - `sum` を桁区切りなしにしているのは、この数値を計算に使うため
- **「Markdown記法を適用せず生のテキストで」** → ChatGPTが ```` ``` ```` で囲んだり装飾したりして、ファイルが崩れるのを防ぐ
- `tags: mrec[date]` → 日付が `YYYY/MM/DD` なので、Obsidianでは `mrec2026` › `11` › `13` の**ネストタグ**になる（狙いどおりか❓要確認）

### 気になった点（記事にするなら直すか触れるか）

- `[info]` は指示1〜3のどこにも定義がない。ChatGPTは文脈で商品一覧（detale）などを入れていると思われる → `[detale]` と書くか、info の中身を指定するとぶれにくい
- `detale` は detail のつづり違い（動作に影響はないが、記事に載せると目立つ）
- `store`（店舗名）は抽出しているのに出力フォーマットに入っていない → フロントマターに `store: [store]` を足すと店舗別に検索できる
- ファイル名（ショートカット側の `name` ＝ 実行した日時）と、フロントマターの `title`（ChatGPTが作る＝レシートの購入日時）は**別物**。指示3の「mdファイルの名前を[title]に」は実際のファイル名には効いていない
